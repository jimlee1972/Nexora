Engineering acceptance remains pending corresponding native CI evidence.

## Native fixture and oracle

`window_presentation.twod_linear_native` submits 42 changing frames to the real native backend.
It compares straight-alpha red-over-gray composition, fixed ACES SDR mapping and a single sRGB
encoding against independent double-precision CPU calculations, with an absolute maximum of two
8-bit values per RGB channel. Gray tint changes every frame and Sprite commands alternate indexed
and instanced paths. Texture IDs intentionally oppose transparent command order.

The matrix covers 320x240, 321x239, 1920x1080, 2520x1080 and 640x480; native resize, bounded target
reuse, black safe-frame bars, blue overlay outside the world viewport, invalid viewport rejection,
zero extent suspension/restore, world without overlay and final target-byte release. The overlay
must retain blue >=253 and red <=2; black bars remain <=2. This is a C++ engine pixel test;
interactive game/diagnostic controls remain a separate Zig deliverable in HD2D-06.

Linux uses Xvfb 3200x1440, Mesa lavapipe 25.0.7 and Khronos validation 1.4.309 with synchronization
validation requested. The scene is rendered by Vulkan; X11 reads the actual presented pixels.
The captured frame, stdout, stderr and launch record remain in CTest artifacts. The final local
fixture passed all 42 frames with no validation error. Software GPU evidence establishes functional
correctness only; no physical display, input or target GPU performance result is inferred.

Windows and macOS compile the same fixture into DX12/Metal native test adapters with GPU staging
readbacks. Their result must come from corresponding CI, not Linux cross compilation. A Metal
host without a device skips explicitly; a skipped native fixture does not satisfy that backend gate.

## Preserved failures and retries

The initial native launch lacked a Vulkan ICD. A task-local official Mesa ICD supplied the missing
software driver without modifying system installation. The first synchronization run identified
SPIR-V DrawParameters without the negotiated device feature; explicit capability query/enable
fixed that issue. Added the world-to-HUD attachment dependency rather than suppressing validation.
The expanded matrix initially expected Ready from a zero-size extent notification; all three
existing backends contractually return ZeroExtent. Corrected that test expectation and retained the
Acquire ZeroExtent assertion. A first cross-compile lacked a writable Zig cache; reran with the
existing task-local cache. Raw failed and successful logs remain in external task evidence.

The first Windows desktop CI on head `5ea3e39d` failed C2628/C2062 because Windows RPC's
`small` macro expanded a new local index variable in Surface.h. Renamed the local and added a
portable pre-include macro regression; no Windows macro is globally undefined by production code.
[Original Windows job](https://github.com/jimlee1972/Nexora/actions/runs/41129328647/job/124316192497).
A separate first-head Linux Shipping job timed out after 90 seconds in the existing Showcase
interaction probe; no HD2D draw was enabled there and its timeout/assertions remain unchanged.
[Original timeout](https://github.com/jimlee1972/Nexora/actions/runs/41129376425/job/124316364204).
The correction also retains native captures in the desktop CI evidence artifact on every OS.
