## Delivered contract

The additive public `BuildFrontend::VerifyArtifacts` requires an exact nonempty
schema-one set of caller-captured `BuildArtifactInput` values with unique relative
identities, matching byte counts and canonical `sha256:` plus 64 lowercase hex
digits. Legacy manifest `Validate`/`Write` serialization stays compatible. Writing
an unchecked manifest or process exit zero still does not certify build success.

Limits are 64 artifacts, 16 MiB each, 64 MiB total, 1024 UTF-8 path bytes, profile
name/target 256 bytes each, configuration 128 bytes and command text 32 KiB.
Complete shape/budget admission precedes hashing. Invalid paths, ASCII controls,
UTF-8 errors, missing/extra/duplicate outputs, size/digest mismatches and unavailable
SHA-256 reject without mutation or IO. No borrowed data survives the call.
The caller owns consistent filesystem capture, expected target completeness,
process outcome, reproducible argv/toolchain/features and future publication.
Command text is descriptive and never executed. Module graph, existing wire schema
and required C/Gameplay ABI are unchanged; public C++ consumers rebuild.

## Actual verification

Actual files produce binary `abc` and empty captures, checked against independent
known SHA-256 vectors in reversed input order. Corruption, omitted/extra/unlisted/
duplicate outputs, byte counts, unsafe paths, canonical checksum spelling, malformed
profile text and path/command limits reject while conserving actual source and
committed manifest files. Unicode identities and exact command/path boundaries pass.
Exact 64-artifact and four 16-MiB zero buffers (64 MiB total) verify actual hashes;
the large-buffer expected value is independently generated by Python `hashlib`.
Count 65, total-budget overflow and per-artifact overflow reject before hashing.
Existing preview/legacy manifest regression tests remain included.
