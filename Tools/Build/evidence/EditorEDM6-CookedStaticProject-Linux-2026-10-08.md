# ED-M6 cooked static-project prerequisites: Linux acceptance

Date: 2026-10-08. Beads tasks: `nexora-62u.1.1` and `nexora-62u.1.2`.
Tested base: main `f21620387e5b27dfb9cce9b341100bb516cc8708`.

## Delivered behavior

Runtime now owns bounded schema-1 mesh, scalar PBR and scene codecs, a validated StaticView
project package, and the optional real `NexoraProjectPlayer --verify-package` executable. This
consumer loads actual World snapshot/AssetCooker/NXAB/BundleBuilder artifacts without Editor or
source lookup. It resolves full UUID dependencies into owning resources and exact world matrices.
It preserves legacy shader IDs and opaque bytes, reports unknown components as inactive, and
rejects unresolved assets, resource collisions, corruption, unsupported schemas and nonfinite data.

[ADR-0006](../../../Roadmap/en/ADR-0006-Cooked-Static-Projects.md), the
[codec contract](../../../Engine/Runtime/CookedSceneAssets.md) and
[package contract](../../../Engine/Runtime/ProjectPackage.md) define wire/ownership/threading,
input/aggregate bounds and borrowed-view lifetime. Checksums are not signatures. Existing NXAB
requires a little-endian host; stable C/Zig and World snapshot formats remain unchanged.

The codecs cover exact vertex/index/opaque bounds, malformed/truncated/trailing data, canonical
ordering, finite geometry, scalar ranges, owning roundtrips and existing Renderer validators.
Package tests cover real asset closure, full-width shader IDs, preserved component names/bytes,
owning lifetime, independent failed candidates, corruption with recomputed outer checksum,
resource collisions, 1,000 shared-mesh instances and a 3,000-level hierarchy. Mirror/nonuniform
parent/shear matrices match the real World matrix; finite local transforms that overflow their
world composition reject. Default Camera projection retains Runtime degree units.

The production CLI tests create genuine Runtime cooked artifacts, invoke the executable as a
separate process, parse JSON independently, and cover Unicode/spaced paths, corruption, missing
files, directory/FIFO/alias input and a sparse file exceeding 256 MiB. Its 64-row diagnostic cap
does not restrict loading: the 1,000-instance fixture reports all resolved/unreported counts.
Fixtures exercise Runtime content; this is not an Editor export acceptance result.

## Environment and required Development gate

Managed Linux cloud; GCC 14.2.0, CMake 3.31.6, Ninja 1.11.1, clang-format 19.1.7. External
dependencies/tool configuration remain outside the repository. Development uses Modular linkage,
graphical shell OFF, Slang OFF and the new Player ON. Existing native tests use Xvfb/lavapipe.

```bash
cmake --preset linux-development -DNEXORA_BUILD_PROJECT_PLAYER=ON -DNEXORA_ENABLE_EDITOR_GRAPHICAL_SHELL=OFF -DNEXORA_ENABLE_SLANG=OFF
cmake --build --preset linux-development -j 2
ctest --preset linux-development
```

✅ Configure and **209 build steps** passed. Full CTest: **90/90 passed, zero skipped,
23.49 seconds**. New production gates are `runtime.cooked_scene_assets`,
`runtime.static_project_package` and `runtime.static_project_player_cli`.
